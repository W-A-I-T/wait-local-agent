# NeoAgent parity matrix

This is a clean-room capability matrix. It compares publicly documented
capability classes with the behavior verified in this repository; it is not a
claim of source, API, wording, or implementation compatibility. The public
NeoAgent documentation is used only as a feature-class reference.

| Capability class | WAIT already has | Partial | Missing | Smallest next implementation |
| --- | --- | --- | --- | --- |
| Bounded agent runtime | Explicit tool allowlists, eight-step cap, timeout, approval pause, redaction, tenant scope, persisted runs | Event context now reaches the same executor | Unrestricted planning and chat | Add narrowly scoped context selection and final-result presentation |
| Tool catalog | Existing smart actions plus read-only local knowledge search, ticket-quality checks, deterministic ticket sentiment and SLA assessment, persisted M365 identity context/user lookup, and preview-only message drafts exposed with schemas, risk, role, approval, and access mode | Most connector/collector capabilities are not catalog entries | Complete connector tool coverage | Wrap one existing read capability at a time |
| Agent definitions | SQLite definitions with enable/disable, trigger, filters, tools, steps, scope, version counter, immutable revision snapshots, redacted diffs, restore-as-new-version, run-to-version links, same-tenant dependencies, and optional IANA-timezone execution windows | `manual`, `scheduled`, and `event` triggers | Overnight windows and richer calendar policies | Add overnight windows only when a concrete operator need is defined |
| Event triggers | Authenticated ticket event ingestion, deterministic filters, idempotency, audit, run-once-per-entity | Supported event vocabulary is intentionally small | Vendor-native webhook adapters and retry queue | Add source validation and bounded retry policy |
| Scheduled workflows | SQLite + APScheduler, cron/interval/one-time schedules with validated IANA timezones, pause/resume/delete/reschedule, workflow and agent targets | Execution windows and richer recurring calendar rules are incomplete | Execution windows and richer recurring calendar rules | Add execution windows without replacing APScheduler |
| Dependencies/chaining | Event agents persist dependency IDs, reject missing/cross-tenant/cyclic relations, and wait for upstream completion in a bounded sequential pass | Event delivery is the supported chain trigger; scheduled workflows do not yet chain | Fan-out/fan-in visualization, cancellation, and workflow-finished chaining | Add explicit dependency execution records and broader trigger support |
| Templates | Fixed public workflow catalog, editable agent definitions, and a tenant-scoped provenance-bearing gallery that resolves to reviewed core implementations | No import/export or marketplace distribution | Pack-backed gallery templates and review lifecycle | Add signed local template packs without allowing arbitrary execution |
| MSP intelligence | Triage, summary, resolution suggestion, similarity, dispatch suggestion, read-only knowledge search, ticket-quality checks, stale/follow-up workflow primitives | Sentiment, SLA, merge, onboarding/offboarding are not unified tools | Broader MSP action catalog | Wrap existing deterministic capabilities before adding models |
| Human approval | Preview, edit, approve/reject, approver identity, gated HaloPSA writes, audited 24-hour default expiry, and late-action blocking | Per-agent policy is incomplete | General approval policy editor | Add policy fields to existing approval records |
| PSA | HaloPSA reads and approval-gated writes plus read-only Autotask, ConnectWise, Syncro, and ServiceNow ticket/company adapters | Shared connector patterns exist | Broader provider-specific mapping | Add the next thin read-only adapter with fakes |
| RMM | Read-only RMM contract plus a NinjaOne adapter for devices, alerts, automation scripts, and non-executing script previews; local endpoint collectors remain available | No script execution, webhook ingestion, or second vendor adapter | NinjaOne, Datto, ConnectWise, N-able, ScreenConnect, Kaseya | Add approved script execution only after connector-scoped credentials and execution records are designed |
| Documentation | Local knowledge ingestion/search, Hudu reads, and read-only IT Glue organization/document/folder lookup | Company/organization scoping remains connector-specific | Confluence and SharePoint adapters | Add one read-only adapter behind existing provider patterns |
| Microsoft 365 | Public governed read-only collector for users, groups, applications, service principals, and Conditional Access policies through `/collectors/modules` and CLI validation/preview/run flows; `m365-identity-context` plus tenant-scoped user/group lookup read completed runs through the agent catalog | No mutation path; licenses, mailbox, and Intune are not yet exposed | Licenses, mailbox, Intune, and approved mutations | Add further bounded read tools over the existing collector/provider contract |
| Communication | Preview-only communication contract and `build-message` tool for ticket notes, email, Teams, Slack, and SMS-shaped drafts; no outbound transport is enabled | Provider adapters and send execution are not shipped | Email, Teams, Slack, SMS adapters | Add one provider adapter with explicit preview, approval, and delivery records |
| Technician teammate | Run-now APIs, tool catalog, execution and approval history | No conversational surface | Technician chat | Reuse runtime through a bounded command surface |
| End-user support | Tenant and approval primitives | No end-user mode | White-label end-user agent | Add after technician surface and safe-tool policy |
| Backfills | `/agent-backfills` provides preflight ticket checks, 100-item bounded sequential execution, progress/count records, pause/cancel state, failed-item reruns, and a no-write dry-run plan with estimated runs/steps, approval requirements, risk, and access mode | No parallel worker pool or cross-provider cost estimate | Cross-connector batch planning and richer operator progress UI | Add connector-specific plans only when a real adapter is available |
| Versioning | Agent `version` increments on update; redacted revision history, field-level diffs, restore-as-new-version, and run identity linked to the exact snapshot are API-accessible | No workflow-template revisions | Revision diff and run identity linked to the exact snapshot | Add workflow-template revisions |
| Observability | Runs, steps, artifacts, approvals, audit, redaction, analytics foundations, exact agent revision links, approval-safe cancellation, and bounded retries | Trigger context is still compact | Provider metadata and richer retry/cancel history | Extend existing execution records, not a new engine |
| Analytics | Local execution counts, outcomes, duration, estimated time saved, client filters, explainable run-kind/trigger/status breakdowns, and approval requested/decided/rate metrics | No dedicated dashboard or ticket-resolution/per-workflow views | Tickets resolved and per-workflow views | Add explainable aggregates to existing analytics |
| API | FastAPI CRUD, run, approval, execution, tools, schedules, event deliveries, revisions/diffs, backfills, run cancel, run retry, NinjaOne read/preview, and Autotask read routes | Connector-specific parity and technician chat remain incomplete | Full parity API surface | Add each capability with tenant/RBAC tests |
| Voice/phone | None by design | None | Voice adapter and caller validation | Defer until core agent and connector paths are stable |

The matrix intentionally keeps missing functionality visible. A row moves to
“already has” only when an operator can exercise it through the public API,
CLI, or dashboard and tests cover the relevant safety boundaries.
