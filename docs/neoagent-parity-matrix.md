# NeoAgent parity matrix

This is a clean-room capability matrix. It compares publicly documented
capability classes with the behavior verified in this repository; it is not a
claim of source, API, wording, or implementation compatibility. The public
NeoAgent documentation is used only as a feature-class reference.

| Capability class | WAIT already has | Partial | Missing | Smallest next implementation |
| --- | --- | --- | --- | --- |
| Bounded agent runtime | Explicit tool allowlists, eight-step cap, timeout, approval pause, active-run cancellation, redaction, tenant scope, persisted runs, and redacted operational final results | Event context now reaches the same executor | Unrestricted planning and chat | Add narrowly scoped context selection |
| Tool catalog | Existing smart actions plus read-only local knowledge search, ticket-quality checks, collector previews, HaloPSA ticket lookup, and Hudu documentation search exposed with schemas, risk, role, approval, and access mode | Collector run/confirmation remains an explicit collector API; broader connector coverage is incomplete | Complete connector tool coverage | Wrap one existing read capability at a time |
| Agent definitions | SQLite definitions with enable/disable, trigger, filters, tools, steps, scope, version counter, immutable revision snapshots, redacted diffs, restore-as-new-version, run-to-version links, and same-tenant dependencies | `manual`, `scheduled`, and `event` triggers | Execution windows | Add execution windows |
| Event triggers | Authenticated ticket event ingestion, deterministic filters, idempotency, audit, run-once-per-entity | Supported event vocabulary is intentionally small | Vendor-native webhook adapters and retry queue | Add source validation and bounded retry policy |
| Scheduled workflows | SQLite + APScheduler, UTC cron/interval/one-time schedules, pause/resume/tenant-scoped reschedule/delete, workflow and agent targets | Execution windows/timezones are intentionally UTC-only | Execution windows/timezones and richer recurring calendar rules | Add execution windows without replacing APScheduler |
| Dependencies/chaining | Event agents persist dependency IDs, reject missing/cross-tenant/cyclic relations, and wait for upstream completion in a bounded sequential pass | Event delivery is the supported chain trigger; scheduled workflows do not yet chain | Fan-out/fan-in visualization, cancellation, and workflow-finished chaining | Add explicit dependency execution records and broader trigger support |
| Templates | Fixed public workflow catalog, editable agent definitions, and a tenant-scoped provenance-bearing gallery that resolves to reviewed core implementations | No import/export or marketplace distribution | Pack-backed gallery templates and review lifecycle | Add signed local template packs without allowing arbitrary execution |
| MSP intelligence | Triage, summary, resolution suggestion, similarity, dispatch suggestion, read-only knowledge search, ticket-quality, deterministic sentiment and escalation assessments, stale/follow-up workflow primitives | SLA timing, merge, onboarding/offboarding are not unified tools | Broader MSP action catalog | Wrap existing deterministic capabilities before adding models |
| Human approval | Preview, edit, approve/reject, approver identity, gated HaloPSA writes, audit | Expiration and per-agent policy are incomplete | General approval policy editor | Add expiry and policy fields to existing approval records |
| PSA | HaloPSA reads, a tenant-scoped HaloPSA ticket tool, approval-gated writes, and read-only ConnectWise PSA, Syncro, ServiceNow, and Autotask routes | Deeper PSA write parity remains incomplete | Broader PSA write parity | Add one bounded read surface at a time |
| RMM | Local endpoint collectors plus a read-only local adapter and bounded device lookup | No third-party RMM adapter or remote-control path | NinjaOne, Datto, ConnectWise, N-able, ScreenConnect, Kaseya | Add one vendor adapter behind the same interface |
| Documentation | Local knowledge ingestion/search, Hudu reads, organization-scoped IT Glue reads, and tenant-scoped Hudu article search tool | Company scoping exists in local records; Confluence and SharePoint are not exposed | Confluence, SharePoint adapters | Add one read-only adapter behind existing provider patterns |
| Microsoft 365 | Code-level adapter groundwork and tenant-scoped read-only identity lookup over collected `m365-user` inventory | Live Graph identity reads and broader resource tools are not yet exposed | Groups, licenses, mailbox, Intune actions | Add a governed live identity read after connector wiring is available |
| Communication | Common preview-only, approval-gated message drafts for email, Teams, Slack, and SMS | No live outbound delivery | Governed connector send adapters | Keep preview and delivery as separate capabilities |
| Technician teammate | Run-now APIs, tool catalog, execution and approval history | No conversational surface | Technician chat | Reuse runtime through a bounded command surface |
| End-user support | Tenant and approval primitives | No end-user mode | White-label end-user agent | Add after technician surface and safe-tool policy |
| Backfills | `/agent-backfills` provides preflight ticket checks, 100-item bounded sequential execution, progress/count records, pause/cancel state, and failed-item reruns | No parallel worker pool or dry-run estimate | Cross-connector batch planning and richer operator progress UI | Add explicit dry-run and connector-aware batch plans |
| Versioning | Agent `version` increments on update; redacted revision history, field-level diffs, restore-as-new-version, and run identity linked to the exact snapshot are API-accessible | No workflow-template revisions | Revision diff and run identity linked to the exact snapshot | Add workflow-template revisions |
| Observability | Runs, steps, artifacts, approvals, audit, redaction, analytics foundations, exact agent revision links, approval-safe cancellation, and bounded retry lineage | Trigger context is still compact | Provider metadata and richer retry/cancel history | Extend existing execution records, not a new engine |
| Analytics | Local execution counts, outcomes, duration, estimated time saved, client filters, and explainable run-kind/trigger/status breakdowns | No dedicated dashboard or ticket-resolution/approval-rate aggregates | Tickets resolved, approval rate, per-workflow views | Add explainable aggregates to existing analytics |
| API | FastAPI CRUD, run, cancel, retry, approval, execution, tools, schedules, event deliveries, revisions/diffs, backfills, and version APIs | Retry policy is intentionally fixed and local; connector-specific parity and technician chat remain incomplete | Full parity API surface | Add each capability with tenant/RBAC tests |
| Voice/phone | None by design | None | Voice adapter and caller validation | Defer until core agent and connector paths are stable |

The matrix intentionally keeps missing functionality visible. A row moves to
“already has” only when an operator can exercise it through the public API,
CLI, or dashboard and tests cover the relevant safety boundaries.
