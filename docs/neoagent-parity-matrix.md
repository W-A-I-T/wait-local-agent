# NeoAgent parity matrix

This is a clean-room capability matrix. It compares publicly documented
capability classes with the behavior verified in this repository; it is not a
claim of source, API, wording, or implementation compatibility. The public
NeoAgent documentation is used only as a feature-class reference.

| Capability class | WAIT already has | Partial | Missing | Smallest next implementation |
| --- | --- | --- | --- | --- |
| Bounded agent runtime | Explicit tool allowlists, eight-step cap, timeout, approval pause, active-run cancellation, redaction, tenant scope, persisted runs, selectable ticket/client/local-knowledge context, and redacted operational final results | Event context now reaches the same executor | Unrestricted planning and chat | Add richer context policies only when an existing source can satisfy them |
| Bounded planning | `POST /agents/plan` and React Agents control select a bounded sequence of existing catalog tools using the configured model provider when available or deterministic rules otherwise; model output is JSON-parsed, catalog-allowlisted, bounded, redacted for remote providers, and falls back safely; plans include tenant-scoped context, expose selection/risk/access/approval metadata without executing, and can create a disabled draft definition for review | Result-aware continuation is opt-in on reviewed definitions; after each successful step it selects one remaining approved tool from the same catalog, records the operational selection mode, and falls back to the reviewed sequence when the provider is unavailable or invalid | Richer reviewed plan generation and broader result-aware policy composition | Extend the existing provider and agent-definition contracts without creating a second runtime |
| Tool catalog | Existing smart actions plus read-only local knowledge search, ticket-quality checks, collector previews, HaloPSA, ConnectWise PSA, Syncro, ServiceNow, and Autotask ticket lookup, Hudu, IT Glue, Confluence, and SharePoint documentation search, RMM operations, communication previews, and approval-gated Microsoft 365 user onboarding/offboarding tools exposed with schemas, risk, role, approval, and access mode | Collector run/confirmation remains an explicit collector API; broader connector coverage is incomplete | Complete connector tool coverage | Wrap one existing capability at a time |
| Agent definitions | SQLite definitions with enable/disable, trigger, filters, tools, steps, scope, selectable context sources, bounded per-agent approval deadlines, opt-in result-aware continuation, version counter, immutable revision snapshots, redacted diffs, restore-as-new-version, run-to-version links, same-tenant dependencies, and optional local execution windows; API and React agent builder | `manual`, `scheduled`, and `event` triggers; windows use validated `HH:MM` bounds and IANA timezones, including overnight ranges | Conversational/unrestricted planning and richer policy composition | Add narrowly scoped policy fields without creating a second runtime |
| Event triggers | Authenticated ticket event ingestion, deterministic filters, idempotency, audit, run-once-per-entity, per-agent attempt state, and a bounded retry queue with per-delivery `max_retries` (0-10) and `retry_delay_seconds` (1-3600) persisted through the API | Supported event vocabulary is intentionally small; retries remain local and batches remain small | Vendor-native webhook adapters and richer trigger policy | Add source validation and further policy only with explicit safety bounds |
| Scheduled workflows | SQLite + APScheduler, cron, interval, and one-time schedules, pause/resume/reschedule/delete, workflow and agent targets, validated IANA schedule timezones, and closed agent windows skipped and audited, plus completion events for scheduled workflow and agent runs | Completion events remain compact and local | Richer schedule-triggered policies | Extend completion events only when an existing bounded event source can satisfy them |
| Dependencies/chaining | Event agents persist dependency IDs, reject missing/cross-tenant/cyclic relations, wait for upstream completion in a bounded sequential pass, and receive automatic tenant-scoped `workflow.completed` events from CLI/API/gallery and scheduled workflow/agent runs | Fan-out/fan-in remains intentionally small | Richer workflow-finished policies and visualization | Extend completion events to other run entry points without creating a second engine |
| Templates | Fixed public workflow catalog, four tool-backed MSP review templates, editable agent definitions, and tenant-scoped gallery instances with editable metadata, enable/disable, revision history, restore-as-new-version, validated versioned JSON import/export, API, CLI, and React UI paths | No marketplace distribution; imports remain disabled until reviewed and gallery behavior remains bounded to reviewed source templates | Pack-backed gallery templates and review lifecycle | Add signed local template packs without allowing arbitrary execution |
| MSP intelligence | Triage, summary, resolution suggestion, similarity, dispatch suggestion, read-only knowledge search, ticket-quality, deterministic sentiment and escalation assessments, explicit-threshold SLA-risk assessment, tenant-scoped stale-ticket sweeps, stale/follow-up workflow primitives, and approval-gated Microsoft 365 user onboarding/offboarding through the shared tool runtime | Ticket merge is not a unified tool; SLA and stale results require ticket timestamps and operator thresholds; onboarding requires a valid local vault reference and offboarding requires both explicit user identity and directory ID | Broader MSP action catalog | Add deterministic lifecycle and client-context tools before adding models |
| Human approval | Preview, edit, approve/reject, approver identity, bounded 24-hour expiry, bounded per-agent deadline shortening, persisted additional approval rules for selected enabled tools, audited expiration, linked-run termination, gated HaloPSA writes, audit | Rules remain additive and agent-scoped; richer role/condition policy composition is incomplete | General approval policy editor with conditional rules | Extend the existing additive policy contract only with stricter, testable conditions |
| PSA | HaloPSA reads, a tenant-scoped HaloPSA ticket tool, approval-gated writes, and ConnectWise PSA ticket/company reads plus approval-gated allowlisted ticket updates; Syncro, ServiceNow, and Autotask read routes | Deeper writes for other PSA providers and richer ConnectWise note/action parity remain incomplete | Broader PSA write parity | Add one bounded write surface at a time |
| RMM | Local endpoint collectors plus tenant-scoped device lookup, alerts, script catalog, script preview, and approval-aware execution; NinjaOne Public API adapter with explicit WAIT-to-organization mapping; Datto RMM devices, open alerts, component metadata, approval-gated quick jobs, and bounded job-status lookup with explicit WAIT-to-site mapping; N-able N-central tenant-scoped devices, active issues, and scheduled-task metadata through a read-only organization-unit map | Broader RMM vendors, richer inventory, and provider-native remediation remain incomplete; N-central execution and execution lookup are intentionally unavailable | ConnectWise, ScreenConnect, Kaseya, and richer N-central remediation | Add one reviewed adapter or bounded capability behind the same contract |
| Documentation | Local knowledge ingestion/search, Hudu reads with bounded article content extraction and tenant-scoped content search, organization-scoped IT Glue document-detail content retrieval, Confluence page body retrieval and tenant-scoped content search, and read-only SharePoint metadata plus bounded text-document content retrieval | Company scoping exists in local records; list-based IT Glue content search, SharePoint binary/office extraction, and list-wide SharePoint content search are not exposed | Broader documentation search and content extraction | Add one read-only adapter behind existing provider patterns |
| Microsoft 365 | Tenant-scoped collected-inventory lookup plus bounded Graph user, group, subscribed-license, per-user license-detail, mailbox-folder, metadata-only message, and Intune managed-device reads; approved user creation, disable/offboarding, strict-ID group membership add/remove, strict-ID direct user license add/remove, approved session revocation, approved Intune managed-device sync/reboot/retirement and remote-lock, allowlisted mailbox-settings updates, message move, message read-state, and message delete updates; the shared tool catalog now exposes approval-gated user onboarding with local-vault credential resolution and disable-then-revoke offboarding with partial-failure reporting | Richer message actions and other device actions are not yet exposed; group, license, device, mailbox, and message mutations remain dedicated approval APIs | Broader message actions and Intune operations | Add one governed M365 mutation at a time with approval |
| Communication | Preview and approval-gated delivery paths for local ticket notes, email, Teams, Slack, and SMS; external adapters use explicit local configuration | PSA-native ticket-note sync and provider-specific delivery features beyond the configured SMTP/webhook adapters | Broader PSA note synchronization, richer provider capabilities, and delivery receipts | Keep preview, approval, and delivery as separate capabilities |
| Technician teammate | Run-now APIs, tool catalog, execution and approval history, technician-only `/technician/chat` and `technician-chat` CLI commands mapped to existing smart actions, persisted tenant/principal-scoped chat sessions with bounded follow-up ticket context and redacted history, and explicit tenant-scoped RMM script preview/approval requests | No free-form planning or external Teams conversation adapter; script requests accept only explicit script/device IDs and still rely on the existing approval flow | Richer conversational context and approved action composition | Add only bounded context or an external channel adapter that reuses the same runtime |
| End-user support | Optional, separately tokenized end-user mode with requester/tenant-scoped local ticket creation, status lookup, and technician escalation | Live PSA ticket synchronization and outbound end-user delivery remain unavailable | White-label end-user agent with governed PSA/communication adapters | Add live adapters behind the same scope boundary |
| Backfills | `/agent-backfills` provides preflight ticket checks, 100-item execution with default sequential or persisted bounded parallelism, progress/count records, pause/cancel state, failed-item reruns, a non-persisting dry-run estimate at `/agent-backfills/preview`, and React dashboard controls | No connector-aware batch planning | Cross-connector batch planning and richer operator progress UI | Add connector-aware batch plans |
| Versioning | Agent `version` increments on update; gallery template versions persist redacted revisions, expose tenant-scoped revision diffs through the API, CLI, and React dashboard, restore as a new version, link gallery runs to the executed template version, and compare workflow runs through API, CLI, and React | Comparison is limited to persisted operational fields; provider metadata and full step-level comparison remain incomplete | Richer revision metadata and step-level run comparison | Extend existing revision views without versioning arbitrary application state |
| Observability | Runs, steps, artifacts, approvals, audit, redaction, analytics foundations, cancelled-run status, bounded retry lineage, per-agent event attempt state, React execution-history detail with technician artifact downloads, and safe provider/model metadata for smart-action runs | Trigger context is still compact | Richer provider metadata and per-step retry history | Extend existing execution records, not a new engine |
| Analytics | Local execution counts, outcomes, duration, estimated time saved, server-side date/client filters, explainable run-kind/trigger/status breakdowns, approval-rate aggregates, current ticket-resolution aggregates, explicit tenant-scoped local/imported ticket status history, recorded historical resolution counts/durations, per-workflow/action activity views, and a React analytics screen | No external-provider lifecycle analytics; existing imported snapshots do not provide inferred historical transitions | Richer provider analytics and connector-aware lifecycle ingestion | Extend existing lifecycle records only when a provider supplies explicit transition evidence |
| Model providers | Deterministic local mode and optional local OpenAI-compatible inference with safe fallback; explicit remote fallback adapters for Anthropic Messages and documented OpenAI-compatible DeepSeek, Kimi, coding-model-compatible, or generic endpoints; explicit offline mode denies remote calls; provider health/configuration is visible without exposing secrets; provider-reported token usage is recorded in redacted execution metadata when supplied | Pricing remains unavailable unless explicitly configured; provider-specific health probes remain incomplete | Broader provider-native capabilities and cost analytics | Extend the single provider boundary with mocked contracts and redacted operational metadata |
| API | FastAPI CRUD, run, cancel, retry, approval, execution, tools, schedules, event deliveries with bounded manual and automatic retry, configurable per-delivery retry policy, backfills, and version APIs | Trigger vocabulary and connector-specific surfaces remain intentionally bounded | Full parity API surface | Add only documented capabilities with tenant/RBAC and failure-path tests |
| Voice/phone | None by design | None | Voice adapter and caller validation | Defer until core agent and connector paths are stable |

The matrix intentionally keeps missing functionality visible. A row moves to
“already has” only when an operator can exercise it through the public API,
CLI, or dashboard and tests cover the relevant safety boundaries.
