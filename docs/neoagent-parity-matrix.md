# NeoAgent parity matrix

This is a clean-room capability matrix. It compares publicly documented
capability classes with the behavior verified in this repository; it is not a
claim of source, API, wording, or implementation compatibility. The public
NeoAgent documentation is used only as a feature-class reference.

| Capability class | WAIT already has | Partial | Missing | Smallest next implementation |
| --- | --- | --- | --- | --- |
| Bounded agent runtime | Explicit tool allowlists, eight-step cap, timeout, approval pause, active-run cancellation, redaction, tenant scope, persisted runs, selectable ticket/client/local-knowledge context, and redacted operational final results | Event context now reaches the same executor | Unrestricted planning and chat | Add richer context policies only when an existing source can satisfy them |
| Tool catalog | Existing smart actions plus read-only local knowledge search, ticket-quality checks, collector previews, HaloPSA ticket lookup, and Hudu documentation search exposed with schemas, risk, role, approval, and access mode | Collector run/confirmation remains an explicit collector API; broader connector coverage is incomplete | Complete connector tool coverage | Wrap one existing read capability at a time |
| Agent definitions | SQLite definitions with enable/disable, trigger, filters, tools, steps, scope, selectable context sources, bounded per-agent approval deadlines, version counter, immutable revision snapshots, redacted diffs, restore-as-new-version, run-to-version links, same-tenant dependencies, and optional local execution windows; API and React agent builder | `manual`, `scheduled`, and `event` triggers; windows use validated `HH:MM` bounds and IANA timezones, including overnight ranges | Conversational/unrestricted planning and richer policy composition | Add narrowly scoped policy fields without creating a second runtime |
| Event triggers | Authenticated ticket event ingestion, deterministic filters, idempotency, audit, run-once-per-entity, and a bounded retry queue with per-agent attempt state | Supported event vocabulary is intentionally small; automatic retries use a local fixed policy and small batch | Vendor-native webhook adapters and configurable retry policy | Add source validation and configurable policy only with explicit safety bounds |
| Scheduled workflows | SQLite + APScheduler, cron, interval, and one-time schedules, pause/resume/reschedule/delete, workflow and agent targets, validated IANA schedule timezones, and closed agent windows skipped and audited | Schedule-triggered chaining remains incomplete | Schedule-triggered chaining | Extend completion events to scheduled entry points without creating a second engine |
| Dependencies/chaining | Event agents persist dependency IDs, reject missing/cross-tenant/cyclic relations, wait for upstream completion in a bounded sequential pass, and receive automatic tenant-scoped `workflow.completed` events from CLI/API/gallery and scheduled workflow/agent runs | Fan-out/fan-in remains intentionally small | Richer workflow-finished policies and visualization | Extend completion events to other run entry points without creating a second engine |
| Templates | Fixed public workflow catalog, four tool-backed MSP review templates, editable agent definitions, and tenant-scoped gallery instances with editable metadata, enable/disable, revision history, restore-as-new-version, API, CLI, and React UI paths | No import/export or marketplace distribution; gallery behavior remains bounded to reviewed source templates | Pack-backed gallery templates and review lifecycle | Add signed local template packs without allowing arbitrary execution |
| MSP intelligence | Triage, summary, resolution suggestion, similarity, dispatch suggestion, read-only knowledge search, ticket-quality, deterministic sentiment and escalation assessments, stale/follow-up workflow primitives | SLA timing, merge, onboarding/offboarding are not unified tools | Broader MSP action catalog | Wrap existing deterministic capabilities before adding models |
| Human approval | Preview, edit, approve/reject, approver identity, bounded 24-hour expiry, bounded per-agent deadline shortening, audited expiration, linked-run termination, gated HaloPSA writes, audit | Per-agent tool-specific rules and richer policy composition are incomplete | General approval policy editor | Add narrowly scoped policy fields to existing approval records |
| PSA | HaloPSA reads, a tenant-scoped HaloPSA ticket tool, approval-gated writes, and read-only ConnectWise PSA, Syncro, ServiceNow, and Autotask routes | Deeper PSA write parity remains incomplete | Broader PSA write parity | Add one bounded read surface at a time |
| RMM | Local endpoint collectors plus tenant-scoped device lookup, alerts, script catalog, script preview, and approval-aware execution; NinjaOne Public API adapter with explicit WAIT-to-organization mapping | NinjaOne is the first live vendor adapter; broader RMM vendors, richer inventory, and provider-native remediation remain incomplete | Datto, ConnectWise, N-able, ScreenConnect, Kaseya | Add one reviewed adapter behind the same contract |
| Documentation | Local knowledge ingestion/search, Hudu reads, organization-scoped IT Glue reads, and read-only Confluence and SharePoint metadata reads | Company scoping exists in local records; file content extraction is not exposed | Richer documentation search and content extraction | Add one read-only adapter behind existing provider patterns |
| Microsoft 365 | Code-level adapter groundwork, tenant-scoped collected-inventory lookup, bounded live Graph user, group, subscribed-license, mailbox-folder, and Intune managed-device context reads, plus approved user creation, disable/offboarding, strict-ID group membership add/remove, strict-ID direct user license add/remove, approved session revocation, approved Intune managed-device retirement, and allowlisted mailbox-settings updates | Per-user license details, message-level mailbox context, and other device actions are not yet exposed | Message actions and broader Intune operations | Add one governed M365 mutation at a time with approval |
| Communication | Preview and approval-gated delivery paths for local ticket notes, email, Teams, Slack, and SMS; external adapters use explicit local configuration | PSA-native ticket-note sync and provider-specific delivery features beyond the configured SMTP/webhook adapters | Broader PSA note synchronization, richer provider capabilities, and delivery receipts | Keep preview, approval, and delivery as separate capabilities |
| Technician teammate | Run-now APIs, tool catalog, execution and approval history, plus technician-only `/technician/chat` and `technician-chat` CLI commands mapped to existing smart actions | No free-form planning, chat history, or script execution command | Richer conversational context and approved action composition | Extend the bounded parser only when a real existing tool can satisfy the request |
| End-user support | Optional, separately tokenized end-user mode with requester/tenant-scoped local ticket creation, status lookup, and technician escalation | Live PSA ticket synchronization and outbound end-user delivery remain unavailable | White-label end-user agent with governed PSA/communication adapters | Add live adapters behind the same scope boundary |
| Backfills | `/agent-backfills` provides preflight ticket checks, 100-item execution with default sequential or persisted bounded parallelism, progress/count records, pause/cancel state, failed-item reruns, and a non-persisting dry-run estimate at `/agent-backfills/preview` | No connector-aware batch planning | Cross-connector batch planning and richer operator progress UI | Add connector-aware batch plans |
| Versioning | Agent `version` increments on update; gallery template versions persist redacted revisions, expose tenant-scoped revision diffs through the API, CLI, and React dashboard, restore as a new version, link gallery runs to the executed template version, and compare workflow runs through API, CLI, and React | Comparison is limited to persisted operational fields; provider metadata and full step-level comparison remain incomplete | Richer revision metadata and step-level run comparison | Extend existing revision views without versioning arbitrary application state |
| Observability | Runs, steps, artifacts, approvals, audit, redaction, analytics foundations, cancelled-run status, bounded retry lineage, and per-agent event attempt state | Trigger context is still compact | Provider metadata and richer per-step retry history | Extend existing execution records, not a new engine |
| Analytics | Local execution counts, outcomes, duration, estimated time saved, client filters, explainable run-kind/trigger/status breakdowns, approval-rate aggregates, current ticket-resolution aggregates, per-workflow/action activity views, and a React analytics screen | No historical resolution timestamps or external-provider analytics | Richer historical ticket lifecycle and provider analytics | Add explicit lifecycle events or provider-specific analytics |
| API | FastAPI CRUD, run, cancel, retry, approval, execution, tools, schedules, event deliveries with bounded manual and automatic retry, backfills, and version APIs | Retry policy is intentionally fixed and local | Full parity API surface | Add configurable policy only with explicit safety bounds and tenant/RBAC tests |
| Voice/phone | None by design | None | Voice adapter and caller validation | Defer until core agent and connector paths are stable |

The matrix intentionally keeps missing functionality visible. A row moves to
“already has” only when an operator can exercise it through the public API,
CLI, or dashboard and tests cover the relevant safety boundaries.
